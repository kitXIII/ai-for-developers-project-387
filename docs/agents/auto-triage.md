# Автотриаж входящих обращений

Второй контур агента: воркфлоу [`triage.yml`](../../.github/workflows/triage.yml) запускается на открытие
issue и делает предварительный разбор. Команду в комментарии никто не пишет — модель работает по этому
документу. От ручного `/oc` прогон отличается ещё и правами: у модели нет доступа на запись.

## Термин

**Входящее обращение** — issue, который создал человек и который не является тикетом процесса: у него
нет state-лейбла из [`triage-labels.md`](triage-labels.md) (`needs-triage`, `needs-info`,
`ready-for-agent`, `ready-for-human`, `wontfix`) и нет лейбла `wayfinder:*`.

Тикеты, которые создают `/to-tickets` и `/to-spec`, уже несут `ready-for-agent`: они подготовлены
к реализации и повторного триажа не требуют. Issue от ботов (например, от процессного App) тоже
не рассматриваются.

Словарь лейблов живёт в [`triage-labels.md`](triage-labels.md). Воркфлоу дублирует пять state-имён
и лейблы `wayfinder:*` в условии запуска, потому что выражения GitHub Actions не читают Markdown:
при смене словаря правьте оба места.

## Кого триажим

Только доверенных авторов: `OWNER`, `MEMBER`, `COLLABORATOR`. Это ограничение не наше, а экшена:
для события `issues` он проверяет `assertPermissions` и требует у автора write-доступ, иначе прогон
падает с `does not have write permissions`. Внешние обращения (автор без write-доступа) автотриажем
не покрываются — это отдельная задача.

## Что делает прогон

1. Читает issue и комментарии (экшен передаёт их в промпт) и проверяет, не реализовано ли уже то,
   о чём просят: ищет по коду через `read`/`grep`/`glob` и по трекеру через `gh issue list --search`.
2. Выбирает ровно одно состояние: `needs-triage` или `needs-info`.
3. Ставит категорию `bug` или `enhancement`, только если она очевидна. Если категория уже стоит,
   вторую не добавляет.
4. Пишет комментарий: дисклеймер, краткое резюме, при нехватке данных — конкретные вопросы.

Прогон не меняет код, не создаёт ветки и PR, не закрывает issue, не ставит `ready-for-*`, не пишет
в `.out-of-scope/` и не трогает другие issue. Эти границы держит не промпт, а конфиг прав: `edit`
запрещён, `bash` разрешён только для чтения трекера, у модели read-only токен, веб-доступ
и инструменты MCP недоступны. Прогон живёт внутри рабочей копии: `external_directory` запрещён,
поэтому пути за её пределами (`$HOME`, `/tmp`) недоступны. Поэтому просьба «поправь код» в тексте
issue закончится ничем.

## Когда данных не хватает

`needs-info` — если в обращении нет того, без чего нельзя начать. Вопросы должны быть конкретными,
не «дайте больше информации», а например:

- для бага: шаги воспроизведения, ожидаемое и фактическое поведение, браузер и устройство, экран
  (тип встречи, слот, шаг мастера бронирования);
- для улучшения: что именно должно измениться для гостя или владельца календаря и как понять,
  что готово.

Если данных достаточно, но категория неочевидна, ставьте `needs-triage` без категории и объясните
в комментарии, что осталось решить человеку.

## Формат комментария

Каждый комментарий начинается с дисклеймера:

```text
> *This was generated by AI during triage.*
```

Дальше — резюме и вопросы. Последняя строка — невидимый маркер, по нему воркфлоу применяет лейблы.
Пример для бага, которому не хватает деталей:

```text
<!-- triage: category=bug state=needs-info -->
```

`category` принимает `bug`, `enhancement` или `none` (категория не выбрана); `state` — `needs-triage`
или `needs-info`. Значения подставляйте свои, а не копируйте перечисление из этого абзаца.

Пост-шаг проверяет значения по белому списку, поэтому маркер не может протащить произвольный лейбл.
Если маркера нет, прогон ставит `needs-triage` и пишет предупреждение в лог.

## Если что-то пошло не так

- Прогона нет: проверьте автора (`OWNER`/`MEMBER`/`COLLABORATOR`), тип автора (бот) и лейблы
  (state-лейбл или `wayfinder:*`).
- Комментарий есть, лейблов нет: в логе шага «Apply triage labels» будет `::warning::` — маркер
  не распознан или значение вне белого списка.
- Лейбл не тот: поправьте вручную; следующего автоматического прогона не будет, событие только
  `issues: [opened]`.
