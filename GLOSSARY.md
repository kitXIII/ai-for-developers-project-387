# Календарь звонков

Сервис бронирования звонков: владелец календаря заранее задаёт типы встреч, а гости записываются на свободное время в его календаре. Без авторизации, личных кабинетов и внешних календарей.

## Language

**Владелец календаря**:
Единственный пользователь сервиса, чьим расписанием управляет приложение; задан заранее.
_Avoid_: админ, администратор, аккаунт

**Гость**:
Тот, кто записывается на встречу, не регистрируясь в сервисе.
_Avoid_: участник, клиент, пользователь

**Тип встречи**:
Вид встречи владельца, определяемый названием, описанием и длительностью.
_Avoid_: услуга, формат, событие

**Слот**:
Свободный интервал в календаре владельца длительностью, равной выбранному типу встречи.
_Avoid_: временной интервал, окошко

**Окно записи**:
Период, в который гость может бронировать: 14 календарных дней, начиная с завтрашнего дня; сегодня и выходные в него входят, но не бронируются.
_Avoid_: период записи, горизонт планирования

**Бронирование**:
Запись гостя на конкретный слот по выбранному типу встречи.
_Avoid_: резерв, заявка, регистрация

**Администрирование**:
Название раздела интерфейса владельца календаря (управление типами встреч и бронированиями). Это имя раздела, а не роль: человеком в системе всегда остаётся только Владелец календаря.
_Avoid_: админ, администратор (как роль или персона)

### Процесс ревью

**Авторевью**:
Ревью pull request отдельным агентом, которое запускается автоматически на событие `pull_request` и публикует замечания комментарием, не меняя код.
_Avoid_: AI-ревью, робот-ревью, автоматическое код-ревью

**Агент-ревьюер**:
Агент, который проводит авторевью: читает diff, спеку и `REVIEW.md`, публикует замечания и не имеет права писать в репозиторий.
_Avoid_: ревьюер-бот, проверяющий агент

**Бюджет запусков**:
Предельное число допущенных команд человека агенту в одном PR-треде, считая попытки запусков; отказы и пропущенные прогоны в него не входят.
_Avoid_: лимит, квота, счётчик команд

**Независимая проверка head SHA**:
Прогон браузерных тестов на точном head SHA pull request в отдельном job, а не на merge-коммите, с трассировкой и артефактом, в имени которого стоит SHA.
_Avoid_: повторный e2e, e2e-head (как название понятия)

**Канал замечаний**:
Место, где человек оставляет команду агенту по pull request: обычный комментарий в обсуждении PR или review-комментарий к строке diff.
_Avoid_: тред, обращение, ревью-тред

**Демонстрационный PR**:
Pull request, на котором показывают оба канала замечаний, поломку теста, исчерпание бюджета, мерж и release-PR.
_Avoid_: демо-PR, показательный PR

**След согласования**:
Ссылки в теле pull request на спеку и комментарий владельца с согласованием, по которым авторевью проверяет, что спека существует и согласована.
_Avoid_: апрув, подтверждение, отметка согласования

**Владелец репозитория**:
Человек, который принимает решение о мерже pull request и меняет настройки GitHub; в этом репозитории совпадает с владельцем календаря, но роль другая.
_Avoid_: мейнтейнер, админ, администратор репозитория
